# Fingerprint (echo-server)

> [English version](README.md)

**Fingerprint** - self-hosted сервис верификации анонимности, написанный на Go. Это TLS/HTTP <echo>-сервер, который анализирует каждое входящее соединение и показывает посетителю, какую именно информацию о нём можно наблюдать со стороны сети: User-Agent браузера, TLS-отпечаток (JA3/JA4), <сырые> TCP/IP-параметры первого SYN-пакета и геолокацию по IP.

Проект предназначен для исследований приватности, проверки качества прокси/VPN и тестирования того, насколько сильно личность клиента <пробивается> через сетевой стек. Веб-панель - это одна страница, которая отображает все собранные данные в отдельных секциях, каждая со своей кнопкой обновления.

## Возможности

- **TLS-фингерпринтинг JA3 и JA4** - <сырой> TLS ClientHello-запись перехватывается и преобразуется в отпечатки JA3 и JA4
- **TCP/IP-фингерпринтинг** - первый TCP SYN-пакет соединения перехватывается на сетевом уровне (libpcap); отображаются полные заголовки IPv4 и TCP: TTL, IP ID, флаги, размер окна, контрольная сумма, urgent pointer и все IP/TCP-опции (MSS, window scale, timestamps и др.)
- **Геолокация по IP** - страна, регион, город, широта/долгота и ISP из бинарной базы IP2Location, с интерактивной картой Leaflet/OpenStreetMap
- **Анализ User-Agent** - заголовок `User-Agent` разбирается и на сервере (Go), и в браузере (ua-parser-js), что позволяет сравнить оба результата на непротиворечивость
- **Самодостаточный бинарник** - веб-панель (HTML/CSS/JS/шрифты) встраивается в исполняемый файл с помощью go-bindata
- **Два HTTPS-слушателя** - порт 443 (стандартный сервер `net/http`: панель + данные) и порт 4443 (uTLS-прокси, перехватывающий ClientHello)
- **Самоподписанный TLS-сертификат**, только HTTP/1.1, keep-alives отключены
- **Грациозное завершение** по SIGINT/SIGTERM
- **Кросс-компиляция** под Windows и Linux (обрезанные, <stripped> бинарники)
- **CLI-флаги**: `-list` (список устройств захвата), `-dev` (индекс устройства захвата), `-ip` (адрес привязки)

## Как это работает

### TLS-фингерпринтинг (JA3 / JA4)

Слушатель на порту 4443 - это uTLS-прокси (fingerproxy). Он перехватывает TLS-рукопожатие и сохраняет <сырую> ClientHello-запись в контексте запроса. Затем запись разбирается (tlsx) и преобразуется в:

- **JA3** - MD5-хеш полей ClientHello (версия TLS, шифры, расширения, эллиптические кривые и т.д.)
- **JA4** - более новый стандарт фингерпринтинга (тип `t` для TLS), дополнительно нормализующий шифры и расширения

В ответе возвращаются оба отпечатка. TLS-конфигурация зафиксирована на HTTP/1.1 (без h2), поэтому отпечаток отражает исключительно TLS-поведение клиента.

### TCP/IP-фингерпринтинг

Фоновая горутина перехватывает пакеты через libpcap (gopacket) с BPF-фильтром: только TCP SYN-пакеты (SYN=1, ACK=0), направленные на IP сервера в порт 443. Для каждого клиентского эндпоинта (`ip:port`) сохраняются полный заголовок IPv4 (версия, IHL, TOS, длина, ID, флаги, фрагментация, TTL, протокол, контрольная сумма, опции) и заголовок TCP (sequence, ack, data offset, окно, контрольная сумма, urgent pointer, опции) в ограниченном по размеру, потокобезопасном хранилище с TTL.

Когда панель запрашивает эндпоинт `/tcp`, обработчик ждёт (до 3 секунд), пока горутина захвата не зафиксирует SYN именно этого соединения, и возвращает заголовок сразу после его появления. Отображаются именно те поля, которые используются для определения ОС/сети и которые рандомизируют приватные инструменты: DF-флаг, IP ID, размер окна, зарезервированные биты, urgent pointer, MSS.

### Геолокация по IP

IP клиента (из соединения) ищется в бинарной базе IP2Location (`IP-COUNTRY-REGION-CITY-LATITUDE-LONGITUDE-ISP.BIN`) методом бинарного поиска по IPv4/IPv6-диапазонам. В ответе - страна (полное/краткое название), регион, город, координаты и ISP, а также ссылка, открывающая карту Leaflet с маркером на координатах клиента.

### Анализ User-Agent

Эндпоинт `/ua` разбирает заголовок `User-Agent` на сервере с помощью regex-парсера и возвращает имя/версию браузера и имя/версию ОС. Панель дополнительно разбирает ту же строку в браузере через ua-parser-js (секция <JS User-Agent>), что позволяет обнаружить несоответствия между двумя результатами.

## Технологии

- **Go 1.24** - весь сервер
- **libpcap / gopacket** - перехват пакетов в реальном времени и декодирование IPv4/TCP
- **uTLS / fingerproxy / tlsx** - перехват TLS ClientHello и вычисление JA3/JA4
- **IP2Location BIN** - бинарная база геолокации
- **go-bindata** - встраивание веб-ассетов в бинарник
- **Bootstrap 5, jQuery** - интерфейс панели
- **Leaflet 1.7.1 + OpenStreetMap** - карта геолокации
- **ua-parser-js** - клиентский разбор User-Agent
- **TLS 1.0-1.3** - сервис работает со всеми версиями TLS; наборы шифров и версии записей служат справочными данными для анализа отпечатков

## Требования

- Go 1.24.9+
- C-компилятор для cgo (пакет `pcap` не является pure-Go):
  - Linux: `build-essential` (gcc)
  - Windows: MinGW-w64 (например, TDM-GCC) с `gcc` в `PATH`
- Библиотека захвата пакетов:
  - Linux: `libpcap` (`libpcap-dev` для сборки)
  - Windows: **Npcap** (рекомендуется) или WinPcap - предоставляет `wpcap.dll`
- Бинарный файл базы IP2Location `IP-COUNTRY-REGION-CITY-LATITUDE-LONGITUDE-ISP.BIN` в рабочей директории
- TLS-сертификат `localhost.crt` / `localhost.key` в рабочей директории
- `go-bindata` (только при пересборке встроенных ассетов)

## Сборка

```sh
# (опционально) перегенерация встроенных ассетов панели после изменения panel/
go-bindata -pkg data -o data/data.go panel/...

# сборка (требуется CGO)
CGO_ENABLED=1 go build -ldflags="-s -w" -trimpath -o echo-server
```

На Windows результатом является `echo-server.exe`. Кросс-компиляция выполняется с `GOOS=linux` / `GOOS=windows` и `GOARCH=amd64` (см. скрипты сборки проекта).

## Запуск

### Linux

```sh
# установка зависимостей
sudo apt-get install build-essential libpcap-dev

# список устройств захвата (для захвата пакетов нужны права root)
sudo./echo-server -list

# запуск: захват на устройстве 0, привязка к IP сервера
sudo./echo-server -dev 0 -ip 1.2.3.4
```

Для захвата пакетов требуются права root (или возможность `CAP_NET_RAW`).

### Windows

```bat
:: 1. установить Npcap (рекомендуется) или WinPcap - предоставляет wpcap.dll
:: 2. запустить терминал от имени Администратора, затем список устройств
echo-server.exe -list

:: 3. запуск: захват на устройстве 0, привязка к IP сервера
echo-server.exe -dev 0 -ip 1.2.3.4
```

Для захвата пакетов терминал должен быть запущен от имени **Администратора**.

## Использование

```sh
echo-server -list                 # список сетевых устройств захвата
echo-server -dev 0 -ip 1.2.3.4    # захват на устройстве 0, привязка к 1.2.3.4
```

| Порт | Назначение |
|---|---|
| 443 | Веб-панель; эндпоинты `/ua` (User-Agent), `/loc` (геолокация), `/tcp` (TCP/IP-отпечаток) |
| 4443 | TLS-отпечаток: JA3 и JA4 ClientHello клиента |

Примеры проверки:

```sh
curl -k https://<ip>:443/ua
curl -k https://<ip>:4443/
```

## Примечание о локальном тестировании (`/tcp`)

Эндпоинт `/tcp` работает за счёт перехвата SYN-пакета клиента на сетевом уровне, поэтому SYN должен физически пройти через захватываемый интерфейс:

- **Тестирование с той же машины не работает.** Соединения с `127.0.0.1` или с собственным IP хоста доставляются через loopback-путь и никогда не проходят через физический NIC, поэтому захват ничего не видит и `/tcp` возвращает пустой результат. Это ожидаемое поведение, а не баг.
- **Windows: WinPcap не умеет захватывать loopback-трафик и виртуальные адаптеры Hyper-V** (WSL, ВМ с vSwitch-сетью). Даже <удалённый> клиент вроде WSL не будет захвачен. Рекомендуется **Npcap** (при установке включите *Loopback support*); он ABI-совместим с WinPcap (`wpcap.dll`) и не требует изменений кода.
- Чтобы протестировать `/tcp`, подключайтесь с **другой машины** в сети (или из ВМ с bridged-сетевым адаптером), чтобы SYN приходил на захватываемый NIC <с провода>.
